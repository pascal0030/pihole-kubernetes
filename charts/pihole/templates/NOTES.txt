Pi-hole Helm Chart Deployment

1. Pi-hole Deployment Information:
   - Release Name: {{ .Release.Name }}
   - Namespace: {{ .Release.Namespace }}
   - Chart Name: {{ .Chart.Name }}
   - Chart Version: {{ .Chart.Version }}
   - Workload Kind: {{ include "pihole.kind" . }}
   - Replicas: {{ .Values.replicaCount }}
{{- if eq (include "pihole.kind" .) "StatefulSet" }}
{{- if include "pihole.useVolumeClaimTemplate" . }}
   - Storage: one PersistentVolumeClaim of {{ .Values.persistentVolumeClaim.size }} per replica
     (config-{{ template "pihole.fullname" . }}-0, config-{{ template "pihole.fullname" . }}-1, ...).
     Every replica keeps its own gravity database, so only its very first boot is slow.
{{- else if .Values.persistentVolumeClaim.enabled }}
   - Storage: all replicas share the PersistentVolumeClaim {{ if .Values.persistentVolumeClaim.existingClaim }}{{ .Values.persistentVolumeClaim.existingClaim }}{{ else }}{{ template "pihole.fullname" . }}{{ end }}.
     Set `statefulset.volumeClaimTemplates.enabled=true` to give every replica its own volume.
{{- else }}
   - Storage: emptyDir, the gravity database is rebuilt on every pod start. Set
     `persistentVolumeClaim.enabled=true` to give every replica a persistent volume.
{{- end }}
   - Each replica is reachable under its own name:
     {{ template "pihole.fullname" . }}-0.{{ include "pihole.statefulset.serviceName" . }}.{{ .Release.Namespace }}.svc.cluster.local
{{- end }}

2. Pi-hole Service Information:
   - Service Name: {{ template "pihole.fullname" . }}-web
   - Service Type: ClusterIP
   - Service Port: 80/443 TCP

   - Service Name: {{ template "pihole.fullname" . }}-dns-tcp
   - Service Type: NodePort
   - Service Port: 53 TCP

   - Service Name: {{ template "pihole.fullname" . }}-dns-udp
   - Service Type: NodePort
   - Service Port: 53 UDP

   - Service Name: {{ template "pihole.fullname" . }}-dhcp
   - Service Type: NodePort
   - Service Port: 67 UDP

3. Accessing Pi-hole:
   !!! This chart does not create a Loadbalancer for pihole by default. Please
   create a configuration that is tailored to your setup. Especially the DNS
   and DHCP services are system services that require a dedicated setup based
   on your system !!!

   Find more information in the wiki:
   https://github.com/MoJo2600/pihole-kubernetes/wiki/Pi%E2%80%90hole

4. Useful Commands:
   - Check the Pi-hole Deployment Status:
     helm status {{ .Release.Name }}

   - Get Detailed Information about the Pi-hole Deployment:
     helm get all {{ .Release.Name }}

5. Clean Up:
   - To uninstall/delete the Pi-hole deployment, run:
     helm uninstall {{ .Release.Name }}
